# rkgk to 3D

졸라맨이나 도형화한 스케치로 잡은 인물 구도를 3D 마네킹 포즈로 바꿔 주는 웹툴 (MVP).
웹에서는 카메라를 돌리고 간단히 보정한 뒤 이미지와 BVH를 내려받고, 손끝 같은 세부는 클립 스튜디오에서 조정한다.

## 실행

Vite로 빌드하는 웹앱(PWA)이다. 화면 절반에 그리고, 나머지 절반에서 3D로 확인한다. Node 20.19 이상이 필요하다.

```sh
npm install
npm run dev       # 개발 서버 → http://localhost:5173
npm run build     # dist/에 배포용 파일 생성
npm run preview   # 빌드 결과 확인 → http://localhost:4173
```

- 서버나 API 없이 전부 브라우저에서 돌아간다. 포즈 인식(MediaPipe)도 브라우저 안에서 실행된다.
- 라이브러리, 글꼴, 인식 엔진(wasm), 기본 인식 모델, 인체 모델을 모두 앱과 함께 배포한다. 외부에서 받는 것은 설정에서 "정밀" 인식 모델(30MB)을 고를 때 Google 저장소에서 받는 파일뿐이다.
- PWA라서 휴대폰·PC에 앱처럼 설치할 수 있고, 한 번 열면 오프라인에서도 동작한다. 첫 방문 때 약 25MB를 받아 둔다. 새 버전은 다음에 열 때 자동으로 적용된다.
- 인식 엔진 wasm은 빌드할 때 `node_modules`에서 `public/mediapipe/`로 복사된다 (`vite.config.js`).

### 배포 (GitHub Pages)

`main`에 올리면 `.github/workflows/deploy.yml`이 빌드해서 GitHub Pages에 배포한다. 처음 한 번, 저장소 **Settings → Pages → Source**를 **GitHub Actions**로 바꿔야 한다. 상대 경로로 빌드하므로 `https://<계정>.github.io/<저장소>/` 같은 하위 경로에서도 동작한다. 다른 정적 호스팅(Cloudflare Pages, Netlify 등)에는 `dist/`를 그대로 올리면 된다.

## 사용법

화면 왼쪽 절반에 그리면 오른쪽 절반의 3D 마네킹이 바로 따라온다. 획을 하나 끝낼 때마다 바뀐 인물만 다시 인식한다. 인식은 백그라운드 워커에서 돌아서 그리는 동안 펜이 끊기지 않는다. 툴바의 **자동 | 수동**(R로 전환)에서 수동을 고르면, 다 그린 뒤 **인식** 버튼(Enter)을 누를 때만 인식한다. 인식 버튼은 아직 인식하지 않은 획이 있을 때만 눌린다.

**그리기 (왼쪽)**
- **색 = 인물:** 색마다 따로 레이어가 있고, 색 하나를 인물 한 명으로 인식한다 (최대 6명). 먼저 그리기 시작한 인물이 뒤, 나중에 그린 인물이 앞이다.
- **펜:** 펜 태블릿·스타일러스는 필압이 굵기에 반영된다. 마우스와 손가락은 일정한 굵기로 그린다.
- **지우개:** 지금 고른 색(인물)의 선만 지운다.
- **라쏘:** 감싼 부분을 떼어 내서 끌어 옮긴다. Delete로 지우고, Esc나 다른 곳 클릭으로 내려놓는다.
- **관절 보기:** 인식된 관절을 그림 위에 점선으로 겹쳐 보여 준다. 빨간 점은 신뢰도가 낮은 관절이다.
- **관절 도구:** 그림 위의 관절 점을 끌어 인식 결과를 고친다 (그림은 그대로). 머리·손목·발목을 옮기면 얼굴·손·발이 따라온다. 고친 관절은 다시 그려도 유지되고, 보정 패널의 "관절 되돌리기"로 지운다.
- 다른 인물에게 가려지는 팔다리도 그려야 한다. 생략하면 그 관절은 추측으로 채워진다.

| 단축키 | 동작 |
| --- | --- |
| Ctrl/⌘ + Z | 되돌리기 (그림과 3D 배치·회전·크기·관절·광원 조작을 순서대로) |
| Ctrl/⌘ + Shift + Z, Ctrl + Y | 다시 하기 |
| B · E · L · V | 펜 · 지우개 · 라쏘 · 관절 도구 |
| R | 자동 · 수동 인식 전환 |
| Enter | 지금 인식 (수동일 때) |
| 1 ~ 6 | 색(인물) 고르기 |
| [ · ] | 굵기 줄이기 · 늘리기 |
| Esc | 라쏘 내려놓기, 선택 해제 |

**3D (오른쪽)**
- 왼쪽 드래그로 회전, 오른쪽 드래그로 이동, 휠로 줌. 카메라를 직접 움직이기 전까지는 그릴 때마다 모든 인물이 보이도록 맞춰지고, 맞추기 버튼을 누르면 다시 자동으로 맞춘다.
- 위쪽 칩이나 마네킹을 누르면 3D 옆에 보정 패널이 열린다: 해석 넘기기(‹ ›), 체형(여/남 · 애니/실사), 몸 앞뒤 반전, 팔다리별 앞뒤 뒤집기, 앞뒤 순서, 크기, 회전. 인형의 밝은 쪽이 왼쪽이고, 팔다리 버튼의 점이 그 밝기를 보여 준다.
- 3D 왼쪽 위의 **배치 | 관절 | 조명**으로 지금 할 일을 고르면 그 손잡이만 보인다.
- **배치:** 인형을 끌면 바닥 위에서 옮겨진다 (사람 사이 거리). 고른 인형에 뜨는 화살표 툴의 축을 끌면 그 방향(위아래 포함)으로만 옮겨진다. 발밑의 고리를 끌거나 보정 패널의 회전 슬라이더로 돌린다.
- **관절:** 고른 인형의 마름모가 관절 손잡이로, 끌면 그 관절이 옮겨진다. 팔꿈치·손목·무릎·발목은 뼈 길이를 지킨 채 방향만 바뀐다.
- 주황 마름모는 신뢰도가 낮은 관절이다. 관절·조명 모드에서는 인형을 눌러 고르기만 하고, 끌면 카메라가 돈다. 인형 위 번호는 고른 인물만 진하게 보인다.
- **조명:** 주황 빛(주 광원, 바닥에 그림자)과 파란 빛(보조 광원)을 끌면 인물들을 둘러싼 구 위에서 빛 방향이 바뀐다. 반대편으로 옮기려면 카메라를 돌린 뒤 끈다. 끌지 않고 누르거나 ⋯ 메뉴의 체크로 각각 켜고 끈다 (꺼진 광원은 흐리게 남는다). 클립 스튜디오의 3D 레이어도 평행 광원 1·2와 환경광 구조라서 주 → 평행 광원 1, 보조 → 평행 광원 2로 옮기면 되지만, 광원 설정을 파일로 불러오는 방법은 없어서 광원 공을 직접 끌어 맞춘다. 묶음 내보내기의 `light-ball.png`에 광원마다 하나씩 비춘 공(카메라에서 본 공, 정면에서 본 공)이 있으니 클립 스튜디오의 공이 그렇게 보이도록 맞춘다. 방향은 묶음 내보내기의 `camera.json`(`lights`)에 담긴다.
- 칩의 "인물 N"과 3D 인형 위의 번호가 같은 인물이고, 색으로도 구별된다.
- 아직 사람으로 인식되지 않은 색은 칩으로만 보이고 3D와 내보내기에서는 빠진다.
- PNG 저장: 현재 시점 그대로 (선택 표시·이름표 제외, 2배 해상도)
- 묶음 내보내기: `view.png` + `sketch.png` + `light-ball.png` + 인물별 `NN_personN.bvh` + `camera.json` + 안내문을 ZIP으로 내려받는다.
- ⋯ 메뉴: 인식 모델, 신뢰도 기준, 주·보조 광원 켜기, 바닥 격자, 카메라 수치

### 인체 모델

인물 카드에서 체형을 고른다: 여/남 × 애니/실사 (기본: 애니 여). 모두 CC0 모델이고 출처는 `public/assets/bodies/CREDITS.txt`에 있다.

| 파일 | 원본 |
| --- | --- |
| `anime-female.glb`, `anime-male.glb` | VRoid Studio 샘플 HairSample_Female / HairSample_Male |
| `real-female.glb`, `real-male.glb` | Quaternius Universal Base Characters (무료판, 히어로 체형) |

포즈 계산과 BVH 내보내기는 `js/mannequin.js`의 뼈대가 맡고, 인체 모델(`js/body.js`)은 그 뼈 회전을 따라 한다. 모델마다 휴지 자세의 팔다리 방향을 우리 뼈대에 맞춰 보정하고, 엉덩이 높이가 같아지도록 크기를 맞춘다.

모델을 다시 만들려면 원본을 받아 둔 뒤 실행한다.

```sh
npm install
npm run build:bodies -- "<Universal Base Characters[Standard]/Base Characters/Godot - UE>" "<HairSample_*.vrm이 있는 폴더>"
```

### 포즈 추출

선 영역을 여백과 함께 잘라 네 가지로 인식해 본다: 원본, 실루엣(선으로 둘러싸인 안쪽을 칠함), 틈 메우기(선을 두껍게 했다가 다시 깎아 끊긴 틈만 메운 뒤 칠함), 두껍게(선을 두껍게 한 뒤 칠함). 첫 결과가 나오는 대로 3D에 바로 보여 주고, 나머지는 이어서 계산해서 주요 관절 신뢰도 평균이 가장 높은 것으로 바꾼다. 점수가 높다고 늘 맞는 해석은 아니므로 보정 패널의 **해석 ‹ ›**로 후보를 바꿔 볼 수 있고, 고른 해석은 다시 그려도 유지된다.

인식은 GPU에서 돌린다. 같은 그림이라도 CPU는 러프한 스케치를 훨씬 못 잡아서, 모델 파일을 한 번 받아 메모리에 두고(끊기면 다시 시도) GPU를 쓸 수 없는 기기에서만 CPU로 돌린다. 그때는 상태 줄과 ⋯ 메뉴의 "인식 장치"에 인식이 약할 수 있다고 표시한다.

면으로 칠한 도형화 스케치가 가장 잘 잡힌다. 선만 있는 러프 스케치는 전처리에 따라 결과가 크게 달라지고, 등을 보이는 자세나 옷에 덮인 몸은 잘 잡히지 않는다.
월드 좌표(m)로 팔다리 방향과 몸통·머리 방향을 맞추고, 팔꿈치와 무릎은 굽는 방향에 맞춰 위팔·허벅지의 비틀림을 정한다.

### 배치

모든 인물에 같은 축척(m/px)을 쓰고 그림 속 엉덩이 위치로 놓는다. 가장 낮은 발이 바닥에 닿게 하고, 순서대로 0.6m씩 앞뒤 간격을 준다. 3D에서 끌어 옮기거나 돌리거나 크기를 바꾼 만큼은 다시 그려도 유지된다.

## 검증 메모 (구상 문서의 [조사-확인 필요] 1번)

합성한 테스트 스케치로 확인한 결과:

- 면으로 칠한 도형화 스케치: 바로 잘 잡힌다.
- 외곽선만 있는 도형화 스케치: 그대로는 인식되지 않지만, 실루엣으로 바꾸면 잡힌다. 다만 앞/뒤(좌우)가 뒤바뀌어 나오는 경우가 있어 "몸 방향 반전"이 필요하다.
- 선 하나로 된 졸라맨: 선을 두껍게 해도 인식되지 않는다. 우회로(이미지 생성 AI)가 필요한 경우다.

실제 손그림으로는 아직 테스트하지 않았다.

## 아직 안 된 것

- 우회로(스케치를 이미지 생성 AI로 사람 이미지로 바꾼 뒤 인식)는 넣지 않았다.
- 클튜에서 BVH가 데생 인형에 제대로 적용되는지, 여러 인물 배치가 유지되는지(구상 문서 3·4번)는 확인하지 못했다. three.js BVHLoader로 다시 읽어 위치가 일치하는 것만 확인했다.
- 웹에서 바꾼 인물 크기는 BVH에 담을 수 없다 (위치에만 반영, `camera.json`에 기록).
