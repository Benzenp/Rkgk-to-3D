# rkgk to 3D

졸라맨이나 도형화한 스케치로 잡은 인물 구도를 3D 마네킹 포즈로 바꿔 주는 웹툴 (MVP).
웹에서는 카메라를 돌리고 간단히 보정한 뒤 이미지와 BVH를 내려받고, 손끝 같은 세부는 클립 스튜디오에서 조정한다.

## 실행

빌드 과정이 없는 정적 페이지다. ES 모듈을 쓰므로 `file://`로는 열리지 않고 정적 서버가 필요하다.

```sh
python3 -m http.server 8000   # → http://localhost:8000
```

GitHub Pages 등에 그대로 올려도 된다. three.js, MediaPipe, fflate, ag-psd는 jsDelivr에서, 포즈 모델은 Google 저장소에서 불러온다.

## 사용법

1. **스케치 올리기:** 인물마다 레이어를 나눈 PNG 여러 장, 또는 레이어가 있는 PSD를 올린다.
   - PSD는 최상위 레이어(또는 폴더) 하나를 인물 한 명으로 본다. 숨긴 레이어와 선이 없는 레이어(용지 등)는 건너뛴다.
   - PNG 여러 장은 파일 이름 순서로 쌓는다 (뒤 → 앞). 목록의 ▲▼로 순서를 바꿀 수 있다.
   - 한 장에 인물마다 색을 달리 그렸다면 "색별로 분리"를 켠다. 검정·회색 선은 어느 인물에도 들어가지 않는다.
2. **인물 목록:** 클튜 레이어 패널처럼 앞(나중 레이어)이 위에 보인다. 썸네일에 인식된 관절이 겹쳐 그려지고, 신뢰도가 기준보다 낮은 관절은 빨간 점(3D에서는 빨간 구)으로 표시된다.
3. **보정:** 인물을 클릭해 선택한다.
   - 몸 방향 반전: 같은 그림을 뒤돌아선 사람으로 다시 해석한다 (깊이 반전 + 좌우 맞바꿈).
   - 왼팔·오른팔·왼다리·오른다리: 그 팔다리의 앞뒤(깊이)를 뒤집는다. 인형의 밝은 쪽이 왼쪽이다.
   - 위치는 화살표를 끌어서, 크기는 슬라이더로 조절한다.
4. **카메라와 저장:** 왼쪽 드래그로 회전, 오른쪽 드래그로 이동, 휠로 줌, 슬라이더로 화각을 조절한다.
   - PNG 저장: 현재 시점 그대로 (선택 표시·이름표 제외, 2배 해상도)
   - 묶음 내보내기: `view.png` + 인물별 `NN_이름.bvh` + `camera.json` + 안내문을 ZIP으로 내려받는다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `js/input.js` | PNG·PSD 읽기, 색별 분리, 선 영역 자르기, 실루엣 변환 |
| `js/pose.js` | MediaPipe Pose Landmarker 실행 (GPU 실패 시 CPU) |
| `js/mannequin.js` | Mixamo식 뼈대 마네킹, 관절 좌표 → 뼈 회전 계산 |
| `js/bvh.js` | 1프레임 BVH 내보내기 (cm, `mixamorig:` 이름, ZXY 회전) |
| `js/viewer.js` | three.js 장면, 카메라, 선택·이동, PNG 캡처, 카메라 수치 |
| `js/main.js` | 화면 연결, 배치, 보정, 내보내기 |

### 포즈 추출

선 영역을 여백과 함께 잘라 원본 → 실루엣(선으로 둘러싸인 안쪽을 칠함) → 선을 두껍게 한 실루엣 순서로 인식해 보고, 주요 관절 신뢰도 평균이 가장 높은 결과를 쓴다. 인식에 실패한 인물은 기본 자세(A자세)로 놓는다.
월드 좌표(m)로 팔다리 방향과 몸통·머리 방향을 맞추고, 팔꿈치와 무릎은 굽는 방향에 맞춰 위팔·허벅지의 비틀림을 정한다.

### 배치

모든 인물에 같은 축척(m/px)을 쓰고 스케치 속 엉덩이 위치로 놓는다. 가장 낮은 발이 바닥에 닿게 하고, 레이어 순서대로 0.6m씩 앞뒤 간격을 준다.

## 검증 메모 (구상 문서의 [조사-확인 필요] 1번)

합성한 테스트 스케치로 확인한 결과:

- 면으로 칠한 도형화 스케치: 바로 잘 잡힌다.
- 외곽선만 있는 도형화 스케치: 그대로는 인식되지 않지만, 실루엣으로 바꾸면 잡힌다. 다만 앞/뒤(좌우)가 뒤바뀌어 나오는 경우가 있어 "몸 방향 반전"이 필요하다.
- 선 하나로 된 졸라맨: 선을 두껍게 해도 인식되지 않는다. 우회로(이미지 생성 AI)가 필요한 경우다.

실제 손그림으로는 아직 테스트하지 않았다.

## 아직 안 된 것

- 우회로(스케치를 이미지 생성 AI로 사람 이미지로 바꾼 뒤 인식)는 넣지 않았다.
- 클튜에서 BVH가 데생 인형에 제대로 적용되는지, 여러 인물 배치가 유지되는지(구상 문서 3·4번)는 확인하지 못했다. three.js BVHLoader로 다시 읽어 위치가 일치하는 것만 확인했다.
- 웹에서 바꾼 인물 크기는 BVH에 담을 수 없다 (위치에만 반영, `camera.json`에 기록).
